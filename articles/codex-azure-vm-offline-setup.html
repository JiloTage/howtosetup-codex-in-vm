Azure VMへのCodex導入ガイド（オフライン環境）

最終更新: 2026-03-26
外部インターネット接続のないAzure VM上にOpenAI Codexを導入する手順を解説する。GitHubからのパッケージ取得、SCPによる転送、Azure OpenAI APIへのマネージドID認証を用いた構成方法を網羅する。

Azure VMへのCodex導入ガイド（オフライン環境）は、外部インターネットへの接続が制限されたAzure仮想マシン上にOpenAI Codex CLIを導入するための包括的な手順書である。企業のセキュリティポリシーにより外部通信が遮断された環境では、npmによるパッケージインストールやOpenAIアカウントへの直接ログインが不可能であるため、代替的なアプローチが必要となる。本ガイドでは、ローカル端末でパッケージを取得しSCPで転送する方式と、Azure マネージドIDを活用したAPI認証によりこの制約を解決する。

前提条件

導入を開始する前に、以下の環境・要件が満たされていることを確認する。

ローカル端末側の要件

  • 外部インターネットへの接続が可能であること
  • Git がインストールされていること
  • Node.js（v18以上）と npm がインストールされていること
  • 対象VMへのSSHアクセス（SCP転送用）が可能であること

Azure VM側の要件

  • Node.js（v18以上）がインストール済みであること（オフライン環境のため事前にインストールが必要）
  • Python 3 がインストール済みであること（トークン取得スクリプトで使用）
  • マネージドIDがVMに割り当て済みであること
  • マネージドIDに対して Azure OpenAI リソースへの「Cognitive Services OpenAI User」ロールが付与されていること
  • Azure OpenAI リソースに適切なモデル（GPT-4等）がデプロイ済みであること

全体構成

本導入方式の全体的なアーキテクチャを以下に示す。ローカル端末からパッケージを取得し、SCPでVMに転送した後、マネージドIDによるトークン取得を経てAzure OpenAI APIに接続する構成となっている。

図1: オフラインAzure VMにおけるCodex導入・認証アーキテクチャ

ステップ1: ローカル端末でのパッケージ準備

まず、インターネットに接続可能なローカル端末でCodex CLIのパッケージを準備する。

1-1. Codexリポジトリのクローン

GitHubからCodex CLIのリポジトリをクローンする。

git clone https://github.com/openai/codex.git
cd codex

特定のリリースバージョンを使用したい場合はタグを指定する。

git clone --branch v0.1.0 --depth 1 https://github.com/openai/codex.git

1-2. パッケージのビルドとtarball作成

依存関係を解決し、転送用のtarballを作成する。

# 依存関係のインストール
npm install

# ビルド（TypeScriptのコンパイル等）
npm run build

# tarball作成
npm pack

これにより openai-codex-x.x.x.tgz のようなファイルが生成される。依存パッケージも含めて転送する必要があるため、node_modules ディレクトリごとアーカイブする方法も検討する。

# node_modulesを含めたアーカイブ作成（依存関係をすべて含む）
tar czf codex-full.tar.gz package.json node_modules/ dist/ bin/

ステップ2: SCPによるVM転送

作成したパッケージをSCPを使ってAzure VMに転送する。

# 単一ファイルの転送
scp codex-full.tar.gz user@vm-hostname:~/

# 踏み台サーバー経由の場合
scp -o ProxyJump=bastion-host codex-full.tar.gz user@vm-private-ip:~/

転送後、VMにSSHでログインしファイルの存在を確認する。

ssh user@vm-hostname
ls -la ~/codex-full.tar.gz

ステップ3: VM上でのインストール

個人ユーザーのホームディレクトリ配下にCodexをインストールする。システムワイドではなくユーザー単位のインストールとするため、$HOME 配下に配置する。

3-1. パッケージの展開

# インストール先ディレクトリの作成
mkdir -p ~/.local/lib/codex
cd ~/.local/lib/codex

# アーカイブの展開
tar xzf ~/codex-full.tar.gz

3-2. 実行パスの設定

# ローカルbinディレクトリの作成とシンボリックリンク
mkdir -p ~/.local/bin
ln -sf ~/.local/lib/codex/bin/codex.js ~/.local/bin/codex

# PATHに追加（.bashrcに追記）
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc

3-3. インストール確認

source ~/.bashrc
codex --version

ステップ4: マネージドID認証の設定

Azure OpenAI APIへのアクセスには、Azure マネージドIDを使用する。これにより、APIキーを静的に保管する必要がなく、セキュリティが向上する。VMに割り当てられたマネージドIDが Azure Instance Metadata Service (IMDS) を通じてOAuthトークンを自動的に取得する仕組みである。

4-1. Azure側のロール割り当て（事前準備）

Azure ポータルまたはAzure CLIで、VMのマネージドIDに対してAzure OpenAIリソースへのアクセス権限を付与する。

# Azure CLIでのロール割り当て例（管理者が実施）
az role assignment create \
  --assignee <VM_MANAGED_IDENTITY_PRINCIPAL_ID> \
  --role "Cognitive Services OpenAI User" \
  --scope /subscriptions/<SUB_ID>/resourceGroups/<RG>/providers/Microsoft.CognitiveServices/accounts/<ACCOUNT>

4-2. .bashrcへのcodex関数の定義

以下の関数を ~/.bashrc に追加する。この関数は、codexコマンド実行のたびにIMDSからアクセストークンを取得し、環境変数として渡す。

codex() {
  local token
  token="$(
    curl --noproxy "*" -fsS -H "Metadata: true" \
      "http://169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01&resource=https://cognitiveservices.azure.com" \
    | python3 -c 'import sys,json; print(json.load(sys.stdin)["access_token"])'
  )" || return 1

  AZURE_OPENAI_API_KEY="$token" command codex "$@"
}

この関数のポイントは以下の通り。

  • curl --noproxy "*": プロキシ設定を無視してIMDS（リンクローカルアドレス）に直接アクセスする
  • -fsS: エラー時にサイレント失敗し、HTTPエラーを検出する
  • -H "Metadata: true": IMDS必須のヘッダー（SSRF対策）
  • resource=https://cognitiveservices.azure.com: Cognitive Services用のトークンを要求
  • python3 -c ...: JSONレスポンスからアクセストークンを抽出
  • command codex: 関数自身の再帰呼び出しを防ぎ、実際のcodexバイナリを実行する

4-3. Azure OpenAI エンドポイントの設定

以下の環境変数も ~/.bashrc に追加する。

# Azure OpenAI エンドポイント設定
export OPENAI_API_BASE="https://<your-resource-name>.openai.azure.com"
export OPENAI_API_TYPE="azure"
export OPENAI_API_VERSION="2024-02-01"

設定後、bashrcを再読み込みする。

source ~/.bashrc

ステップ5: 動作確認

すべての設定が完了したら、動作確認を行う。

5-1. トークン取得の確認

まず、マネージドIDによるトークン取得が正常に動作するか単体で確認する。

curl --noproxy "*" -fsS -H "Metadata: true" \
  "http://169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01&resource=https://cognitiveservices.azure.com" \
  | python3 -c 'import sys,json; t=json.load(sys.stdin); print("Token acquired, expires:", t.get("expires_on", "unknown"))'

5-2. Codex CLIの実行テスト

# 簡単なプロンプトで動作確認
codex "Hello, world!"

正常に応答が返れば導入は完了である。

トラブルシューティング

トークン取得の失敗

  • 症状: curl: (7) Failed to connect — IMDSに到達できない
  • 原因: VMにマネージドIDが割り当てられていない、またはネットワーク設定の問題
  • 対処: Azureポータルで「ID」設定を確認し、システム割り当てマネージドIDが「オン」であることを確認する

403 Forbidden エラー

  • 症状: Azure OpenAI APIから403が返る
  • 原因: マネージドIDに適切なロールが割り当てられていない
  • 対処: 「Cognitive Services OpenAI User」ロールの割り当てを確認する。ロール反映には数分かかる場合がある

Node.jsバージョンの問題

  • 症状: SyntaxError: Unexpected token 等のエラー
  • 原因: Node.jsのバージョンが古い
  • 対処: node --version でバージョンを確認し、v18以上であることを確認する。オフライン環境でのNode.jsアップデートについてはNode.jsオフラインインストールを参照

プロキシ関連の問題

  • 症状: IMDSへのアクセス時にプロキシ経由で接続しようとしてエラーになる
  • 対処: curl --noproxy "*" のフラグが正しく設定されていることを確認する。また、no_proxy 環境変数に 169.254.169.254 を追加することも有効
# .bashrcに追加
export no_proxy="169.254.169.254,$no_proxy"
