OpenAI Codex CLI概要

最終更新: 2026-03-26
OpenAI Codex CLIは、ターミナル上で自然言語の指示をもとにコードの生成・編集・実行を行うオープンソースのコマンドラインエージェントである。本記事ではその機能、アーキテクチャ、対応モデル、主要コマンドおよび活用事例を解説する。

OpenAI Codex CLIは、OpenAIがGitHub上でオープンソースとして公開しているコマンドラインインターフェースツールである。ターミナルから自然言語で指示を与えることで、コードの生成、既存ファイルの編集、シェルコマンドの実行などを対話的に行うことができる。従来のCodex API（2023年に廃止）とは異なり、本ツールはローカル環境で動作するCLIエージェントであり、GPT-4oやo3-mini、o4-miniなどのモデルを活用してソフトウェア開発タスクを自動化する。Azure VMへのオフライン導入も可能であり、企業環境での利用にも対応している。

主な機能

Codex CLIは、単なるコード補完ツールではなく、開発ワークフロー全体を支援するエージェント型ツールとして設計されている。

コード生成と編集

自然言語の指示に基づいて新規コードの生成や既存ファイルの修正を行う。プロジェクトのコンテキストを読み取り、コードスタイルや構造に沿った変更を提案する。複数ファイルにまたがる修正にも対応しており、リファクタリングや機能追加を効率的に実行できる。

シェルコマンドの実行

テスト実行、ビルド、リンター呼び出しなどのシェルコマンドを自律的に実行する機能を持つ。実行結果を解析し、エラーがあれば修正案を提示する。これにより、コード変更からテスト確認までのサイクルを自動化できる。

サンドボックス実行

安全性を確保するため、コマンド実行にはサンドボックスが適用される。macOSではApple Seatbelt、Linuxではdockerベースのサンドボックスにより、ファイルシステムやネットワークへのアクセスが制限される。これにより、意図しない破壊的操作からシステムを保護する。

マルチモーダル入力

テキストだけでなく、スクリーンショットや画像を入力として受け付ける。UIのモックアップ画像からコードを生成したり、エラー画面のスクリーンショットからデバッグを行うといった活用が可能である。

対応モデル

Codex CLIは、OpenAIのResponses APIを通じて複数のモデルに対応している。デフォルトではo4-miniが使用され、コストと性能のバランスに優れている。

モデル名 特徴 推奨用途
o4-mini 高速・低コスト、デフォルトモデル 日常的な開発タスク全般
o3-mini 推論能力に優れたコンパクトモデル 複雑なロジックの実装
GPT-4o マルチモーダル対応、高い汎用性 画像入力を伴うタスク
GPT-4.1 コーディング特化の最新モデル 大規模コードベースの解析

モデルは --model フラグで切り替え可能である。また、Azure OpenAIやOpenAI互換エンドポイント（Ollama、vLLM等）を通じたローカルモデルの利用にも対応しており、オフライン環境への導入時にはマネージドID認証と組み合わせてAzure OpenAIを使用する。

CLIコマンドとオプション

Codex CLIの基本的な使い方と主要オプションを以下に示す。

基本的な使用法

# 対話モード（引数なしで起動）
codex

# ワンショットモード（プロンプトを直接指定）
codex "Pythonで素数判定関数を作成して"

# パイプ入力
cat error.log | codex "このエラーの原因を分析して"

主要オプション

オプション 説明 例
--model, -m 使用するモデルを指定 codex -m gpt-4o "..."
--approval-mode, -a 承認モードを設定 codex -a auto-edit "..."
--quiet, -q 出力を最小限にする codex -q "..."
--full-auto 全操作を自動承認（要注意） codex --full-auto "..."
--image, -i 画像ファイルを入力に追加 codex -i screenshot.png "..."

承認モード詳細

Codex CLIは安全性のため、操作の承認レベルを3段階で制御できる。

  • suggest（デフォルト）: すべてのファイル変更とコマンド実行をユーザーに確認する。最も安全なモード
  • auto-edit: ファイルの読み書きは自動的に承認されるが、シェルコマンドの実行には確認を求める
  • full-auto: すべての操作を自動的に実行する。サンドボックスによる保護は有効だが、意図しない変更のリスクがあるため注意が必要

設定とカスタマイズ

Codex CLIは、プロジェクト単位およびユーザー単位の設定ファイルにより動作をカスタマイズできる。

カスタム指示（instructions）

プロジェクトのルートディレクトリに AGENTS.md（または codex.md）ファイルを配置することで、Codex CLIにプロジェクト固有の指示を与えることができる。コーディング規約、使用するフレームワーク、テスト方針などを記載すると、それに従ったコード生成が行われる。

環境変数による設定

主要な設定は環境変数で制御できる。

# OpenAI APIキー
export OPENAI_API_KEY="sk-..."

# Azure OpenAI 使用時
export OPENAI_API_BASE="https://<resource>.openai.azure.com"
export OPENAI_API_TYPE="azure"
export OPENAI_API_VERSION="2024-02-01"

# プロキシ設定
export HTTPS_PROXY="http://proxy:8080"

Azure VMへのCodex導入ガイドでは、マネージドIDを利用してAPIキーなしで認証する方法を詳しく解説している。Azure IMDSを経由したトークン取得により、静的な認証情報の管理が不要となる。

活用事例

Codex CLIは多様な開発シーンで活用できる。以下に代表的なユースケースを示す。

コードリファクタリング

既存のコードベースに対し、「この関数をTypeScriptに変換して」「重複コードをユーティリティ関数に抽出して」といった指示で大規模なリファクタリングを効率的に実行できる。複数ファイルにまたがる変更も一度の指示で対応可能である。

テスト生成

「このモジュールのユニットテストを作成して」という指示で、既存コードの構造を解析し、適切なテストケースを自動生成する。カバレッジの向上やエッジケースの発見に有効である。

デバッグ支援

エラーログやスタックトレースを入力として渡すことで、原因の分析と修正案の提示を行う。プロンプトエンジニアリングの手法を活用することで、より精度の高い解析が可能となる。

オフライン環境での利用

企業のセキュリティポリシーにより外部通信が制限された環境でも、オフラインセットアップ手順に従いSCPによるパッケージ転送とNode.jsのオフラインインストールを行うことで利用可能である。
